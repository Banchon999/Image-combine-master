# 🧩 Imbine — แอพต่อภาพเว็บตูน

โปรแกรมต่อภาพ (เว็บตูน / มันฮวา / มังงะ) พร้อม interactive workspace เขียนด้วย
Python + Qt (PySide6) รันได้ทั้ง Windows / macOS / Linux

ส่วนตรรกะแยกออกจาก UI สมบูรณ์ — เอาไป import ใช้ในสคริปต์อื่นได้ และรองรับ
การเสียบขั้นตอนใหม่ (upscale, denoise ฯลฯ) โดยไม่ต้องแก้โค้ดเดิม

## ✨ ฟีเจอร์

- **ต่อได้ 2 ทิศทาง** — แนวตั้ง (สำหรับเว็บตูน) และแนวนอน
- **เรียงภาพอัตโนมัติ** ด้วย natural sort — `1, 2, 3, ... 10, 11` ไม่ใช่ `1, 10, 11, 2`
  รองรับชื่อไฟล์หลายรูปแบบ เช่น `01.jpg`, `page_10.jpg`, `001-002.jpg`, `ตอนที่ 1.jpg`
- **แถบสรุปผลแบบเรียลไทม์** — บอกตลอดเวลาว่าจะได้กี่ไฟล์ ไฟล์ละกี่พิกเซล ประมาณกี่ MB
  โดยไม่ต้องกดอะไรเลย
- **พรีวิวผลลัพธ์จริงก่อนส่งออก** — ต่อภาพจริงให้ดูในแอพ ย่อขนาดอัตโนมัติเพื่อไม่ให้กินแรม
- **เตือนก่อนชนลิมิตของ format** — WebP เก็บได้สูงสุด 16,383 px, JPEG 65,535 px
  ระบบบอกตั้งแต่ก่อนเริ่มทำงาน ไม่ใช่ไปพังตอนบันทึก
- **แบ่งไฟล์ผลลัพธ์ได้ 2 แบบ** — กำหนดจำนวนไฟล์ หรือจำกัดความสูง/กว้างต่อไฟล์ (px)
- **ตั้งชื่อไฟล์ด้วย pattern** — `{n}` `{n2}` `{n3}` `{folder}` `{total}` พร้อมปุ่มกดแทรก
- **ออกไฟล์ได้ 4 ชนิด** — JPG / PNG / WebP / TIFF พร้อมปรับคุณภาพ
- **ตัดขอบอัตโนมัติ** — ตัดขอบสีเดียวรอบภาพ และตัดส่วนที่หน้าถัดไปซ้ำกับหน้าก่อน
- **ใส่ลายน้ำ** — ข้อความหรือรูปภาพ วางได้ 9 ตำแหน่ง ปรับความเข้มได้ (รองรับภาษาไทย)
- **พรีเซ็ต** — เก็บค่าตั้งทั้งชุดไว้ใช้ซ้ำ เป็นไฟล์ JSON ที่ส่งต่อให้เพื่อนได้
- **สองภาษา ไทย/English** — สลับได้ทันทีจากเมนู และเพิ่มภาษาอื่นได้โดยไม่ต้องแก้โค้ด
- **ธีมมืด/สว่าง**
- **ลากไฟล์หรือโฟลเดอร์มาวางได้เลย** และมีคีย์ลัดครบ
- **โหมดหลายโฟลเดอร์** — ต่อภาพหลายตอนรวดเดียว เพิ่มโฟลเดอร์ย่อยทั้งหมดได้ในคลิกเดียว
- **ระบบ smart กัน human error** — ตรวจสอบก่อนเริ่มทำงานทุกครั้ง แล้วสรุปคำเตือนให้ยืนยัน
- **ยกเลิกงานกลางคันได้** — ไม่ต้องรอจนจบหรือฆ่าโปรเซสทิ้ง

## 🚀 วิธีใช้

### หน้าต่างหลัก

แผงตั้งค่าทางขวาเรียงตามลำดับที่คนคิดจริง ๆ เวลาต่อภาพ:

| กลุ่ม | ตั้งอะไร |
|------|---------|
| 1 · ต่อไปทางไหน | แนวตั้ง (เว็บตูน) หรือแนวนอน |
| 2 · แบ่งเป็นกี่ไฟล์ | กำหนดจำนวนไฟล์ **หรือ** จำกัดขนาดต่อไฟล์ (เลือกได้อย่างเดียว) |
| 3 · ไฟล์ผลลัพธ์ | ชนิดไฟล์, คุณภาพ, ปรับขนาดให้เท่ากัน, เขียนทับ |
| 4 · ชื่อไฟล์ | pattern พร้อมปุ่มกดแทรกตัวแปร และพรีวิวชื่อจริง |
| 5 · ตกแต่งเพิ่มเติม | ตัดขอบ, ตัดส่วนซ้ำ, ลายน้ำ |
| 6 · พรีเซ็ต | บันทึก/โหลดค่าตั้งทั้งชุด |

### ขั้นตอน

1. ลากโฟลเดอร์มาวาง หรือกด **นำเข้าทั้งโฟลเดอร์** — ระบบเรียงลำดับให้อัตโนมัติ
2. ดู **แถบสรุป** ใต้แถบเครื่องมือว่าจะได้ผลลัพธ์อะไร ถ้ามีคำเตือนจะขึ้นสีเหลืองตรงนั้น
3. ตรวจลำดับใน "ภาพที่นำเข้า" ด้านล่าง ลากสลับได้ตามต้องการ
4. กด **พรีวิว** (`Ctrl+P`) เพื่อดูผลลัพธ์จริง
5. กด **ส่งออก** (`Ctrl+E`) ระบบ Smart Check จะตรวจก่อนเริ่ม

### คีย์ลัด

| คีย์ | ทำอะไร |
|-----|-------|
| `Ctrl+O` | นำเข้าไฟล์ภาพ |
| `Ctrl+Shift+O` | นำเข้าทั้งโฟลเดอร์ |
| `Ctrl+P` | สร้างพรีวิว |
| `Ctrl+E` | ส่งออก |
| `Ctrl+Z` / `Ctrl+Y` | เลิกทำ / ทำซ้ำ |
| `Delete` | ลบภาพที่เลือก |

### ต่อหลายโฟลเดอร์

1. เปิดแท็บ **ต่อหลายโฟลเดอร์**
2. กด **เพิ่มโฟลเดอร์** ทีละรายการ หรือ **เพิ่มทุกโฟลเดอร์ย่อย** เพื่อเพิ่มทุกตอนในโฟลเดอร์แม่
3. ลากเรียง queue เลือกปลายทาง และเลือกว่าจะแยกโฟลเดอร์ผลลัพธ์ตามชื่อตอนไหม
4. กด **เริ่มต่อทุกโฟลเดอร์** — ระบบตรวจทุกงานก่อนเริ่มและทำงานต่อแม้บางโฟลเดอร์ล้มเหลว

## 🏷️ รูปแบบชื่อไฟล์ (name pattern)

| ตัวแปร     | ความหมาย                | ตัวอย่างผลลัพธ์ |
|-----------|------------------------|----------------|
| `{n}`     | เลขลำดับ                 | `1`, `2`, `3`   |
| `{n2}`    | เลขลำดับ 2 หลัก           | `01`, `02`      |
| `{n3}`    | เลขลำดับ 3 หลัก           | `001`, `002`    |
| `{folder}`| ชื่อโฟลเดอร์ต้นทาง         | `ตอนที่-12`     |
| `{total}` | จำนวนไฟล์ผลลัพธ์ทั้งหมด    | `5`            |

**ตัวอย่าง**

| Pattern              | ได้ไฟล์               |
|----------------------|----------------------|
| `{n3}`               | `001.jpg`            |
| `{folder}_{n2}`      | `ตอนที่-12_01.jpg`    |
| `page {n} of {total}`| `page 1 of 5.jpg`    |

> อักขระต้องห้ามของระบบไฟล์ (`< > : " / \ | ? *`) จะถูกแทนด้วย `_` ให้อัตโนมัติ

## 🛡️ ระบบกัน human error ตรวจอะไรบ้าง

ก่อนเริ่มต่อภาพจริง โปรแกรมจะสแกนแล้วเตือนเมื่อเจอ:

- **ไฟล์เสีย / เปิดไม่ได้** — บอกจำนวนและชื่อไฟล์ แล้วข้ามให้
- **ความกว้างต่างกันมาก** (แคบสุด < 50% ของกว้างสุด) — อาจเป็นภาพคนละชุด
- **ภาพที่ขนาดผิดปกติ** เทียบกับค่ามัธยฐาน — มักเป็นปก / โฆษณา / ภาพแทรก
- **ปลายทางอยู่ในต้นทาง** — จะทำให้รอบหน้าเอาไฟล์ที่ต่อแล้วมาต่อซ้ำ
- **ชื่อไฟล์ซ้ำในปลายทาง** — ถ้าไม่ได้ติ๊กเขียนทับ ระบบเติม `_1`, `_2` ให้
- **ขนาดเกินลิมิตของ format** — บอกตั้งแต่ตอนเลือกค่าตั้ง ไม่ใช่ตอนบันทึกไม่สำเร็จ

ทุกอย่างเป็นแค่ "คำเตือน" — คนตัดสินใจเองว่าจะไปต่อหรือยกเลิก

├── resources.py     หา path ไฟล์ประกอบ ทั้งตอนรันจาก source และตอนเป็น .exe
├── images.py        ค้นหา + เรียงไฟล์ภาพ (natural sort)
├── inspection.py    ระบบกัน human error (ตรวจก่อนทำงาน)
├── estimate.py      ประมาณผลล่วงหน้าจากขนาดไฟล์ ไม่ต้อง decode

├── grouping.py      แบ่งภาพเป็นกลุ่ม (1 กลุ่ม = 1 ไฟล์ผลลัพธ์)
├── compose.py       งานพิกเซล: เปิดไฟล์ / ปรับขนาด / วางลงผืนผ้าใบ
├── trim.py          ตัดขอบว่างและตัดส่วนซ้ำระหว่างหน้า
├── watermark.py     ใส่ลายน้ำข้อความ/รูปภาพ
├── output.py        บันทึกเป็น JPG / PNG / WebP / TIFF
├── userdata.py      ค่าตั้งของผู้ใช้และพรีเซ็ต
├── pipeline.py      กลไกท่อประมวลผล + ยกเลิกงาน + รายงานความคืบหน้า
├── steps/           ขั้นตอนมาตรฐาน (load, trim, downscale, uniform,
│                    split, stitch, watermark, save)
├── api.py           run_stitch() — หน้าบ้านที่ UI เรียก
└── ui/qt/           หน้าต่าง Qt (ส่วนเดียวที่รู้จัก UI)

และ workflow ก็ตรวจซ้ำอีกชั้น

## 🔧 ท่อประมวลผล (pipeline)

การต่อภาพถูกแยกเป็น "ขั้นตอน" ที่ต่อกันเป็นสาย:

```
load → trim → downscale → uniform → split → stitch → watermark → save
```

`trim`, `downscale` และ `watermark` **ปิดอยู่เป็นค่าเริ่มต้น** สายที่รันจริงจึงเหลือ
`load → uniform → split → stitch → save` เหมือนเดิมจนกว่าผู้ใช้จะเปิดใช้เอง

แต่ละขั้นเปิด/ปิด/แทรก/สลับได้ทีละตัว ระบบที่จะเพิ่มทีหลัง (upscale, denoise)
เสียบเข้ามาโดยไม่ต้องแก้โค้ดเดิม:

```python
from imbine import Step, build_default_pipeline, run_stitch

class UpscaleStep(Step):
    name = "upscale"

    def run(self, ctx):
        ...  # ขยายภาพทุกใบใน ctx.images

pipe = build_default_pipeline()
pipe.insert_after("load", UpscaleStep())

run_stitch(paths, "output", pipeline=pipe)
```

ทุกขั้นต้องเคารพ 4 ข้อ:

1. รายงานผ่าน `ctx.progress`
2. เช็ค `ctx.cancel` ในลูปที่กินเวลา
3. ห้ามแตะ UI
4. `is_enabled()` **ตัดสินใจจาก `ctx.config` เท่านั้น** — `Pipeline.run` เรียกเมธอดนี้
   ของทุกขั้นก่อนเริ่มรัน ตอนนั้น `ctx.images` ยังว่างอยู่เสมอ

## 🧪 เรียกใช้เป็นไลบรารีก็ได้

```python
from imbine import image_paths_in, run_stitch, StitchConfig

ctx = run_stitch(
    image_paths_in("chapter_01"),
    output_folder="output",
    config=StitchConfig(orientation="vertical", parts_count=3,
                        name_pattern="{folder}_{n2}", fmt="JPG"),
    folder_name="chapter_01",
    progress_cb=lambda e: print(f"[{e.step}] {e.done}/{e.total}"),
)
print(ctx.saved_paths)
```

**ประมาณผลก่อนทำจริง** (อ่านแค่ส่วนหัวไฟล์ เร็วมาก):

```python
from imbine import plan_for_paths, human_bytes, StitchConfig

plan = plan_for_paths(image_paths_in("chapter_01"), StitchConfig(fmt="WEBP"))
print(plan.part_count, plan.parts, human_bytes(plan.total_bytes))
for warning in plan.warnings:
    print(warning)      # เช่น เตือนว่าจะเกินลิมิต 16383 px ของ WebP
```

**ยกเลิกกลางคัน** (สั่งจากอีกเธรดได้):

```python
from imbine import CancelToken, Cancelled

token = CancelToken()
try:
    run_stitch(paths, "output", cancel=token)
except Cancelled:
    print("ผู้ใช้ยกเลิก")
```

**เปลี่ยนภาษาของข้อความที่ไลบรารีคืนกลับมา:**

```python
from imbine import set_locale, inspect_images

set_locale("en")
for warning in inspect_images(paths).warnings:
    print(warning)      # คำเตือนออกมาเป็นภาษาอังกฤษ
```

**ปล่อย `output_folder` ว่าง = ไม่เขียนไฟล์** ได้ภาพในหน่วยความจำอย่างเดียว

## ⚠️ ข้อจำกัดที่ควรรู้

- **ลิมิตขนาดของ format** — JPEG กว้าง/สูงได้ไม่เกิน 65,535 px, WebP ไม่เกิน 16,383 px
  โปรแกรมเตือนให้ตั้งแต่ก่อนเริ่ม ให้ใช้ "จำกัดขนาดต่อไฟล์" หรือเปลี่ยนไปใช้ PNG
- ภาพถูกโหลดเข้าหน่วยความจำทั้งหมดก่อนต่อ — โฟลเดอร์ใหญ่มากอาจใช้ RAM เยอะ
  (โหมดพรีวิวย่อภาพให้อัตโนมัติ จึงไม่มีปัญหานี้)
- เรียงลำดับตาม "ชื่อไฟล์" เท่านั้น ถ้าชื่อไม่สื่อลำดับ ให้เปลี่ยนชื่อไฟล์ก่อน
- โหมดจำกัดขนาดต่อไฟล์ตัดได้เฉพาะ "ตรงรอยต่อระหว่างภาพ" — ยังไม่มีระบบตัดกลางภาพ
  แบบเลี่ยงบอลลูนคำพูด
