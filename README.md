# 🧩 ImageStitcher — แอพต่อภาพเว็บตูน

โปรแกรมต่อภาพ (เว็บตูน / มันฮวา / มังงะ) แบบมี UI ครบครัน เขียนด้วย Python + PySide6
รันได้ทั้ง Windows / macOS / Linux (Tkinter UI เดิมยังเก็บไว้เป็น legacy frontend)

ส่วนตรรกะแยกออกจาก UI สมบูรณ์ — เอาไป import ใช้ในสคริปต์อื่นได้ และรองรับ
การเสียบขั้นตอนใหม่ (upscale, watermark ฯลฯ) โดยไม่ต้องแก้โค้ดเดิม

---

## ✨ ฟีเจอร์

- **ต่อได้ 2 ทิศทาง** — แนวตั้ง (สำหรับเว็บตูน) และแนวนอน
- **เรียงภาพอัตโนมัติ** ด้วย natural sort — `1, 2, 3, ... 10, 11` ไม่ใช่ `1, 10, 11, 2`
  รองรับชื่อไฟล์หลายรูปแบบ เช่น `01.jpg`, `page_10.jpg`, `001-002.jpg`, `ตอนที่ 1.jpg`
- **แบ่งไฟล์ผลลัพธ์ได้ 2 แบบ** — กำหนดจำนวนไฟล์ หรือจำกัดความสูง/กว้างต่อไฟล์ (px)
- **ตั้งชื่อไฟล์ด้วย pattern** — `{n}` `{n2}` `{n3}` `{folder}` `{total}`
- **ออกไฟล์ได้ 3 ชนิด** — JPG / PNG / WebP พร้อมปรับคุณภาพ
- **ปรับขนาดให้เท่ากันทุกภาพ** ก่อนต่อ (แนวตั้ง = กว้างเท่ากัน, แนวนอน = สูงเท่ากัน)
- **โหมดหลายโฟลเดอร์** — ต่อภาพหลายตอนรวดเดียว เพิ่มโฟลเดอร์ย่อยทั้งหมดได้ในคลิกเดียว
- **ระบบ smart กัน human error** — ตรวจสอบก่อนเริ่มทำงานทุกครั้ง แล้วสรุปคำเตือนให้ยืนยัน
- **ยกเลิกงานกลางคันได้** — ไม่ต้องรอจนจบหรือฆ่าโปรเซสทิ้ง

## 🚀 วิธีใช้

```bash
python -m imbine
```

โปรแกรมมี 2 แท็บ:

### แท็บ 1 — ต่อภาพ 1 โฟลเดอร์

1. เลือกโฟลเดอร์ต้นทางที่มีรูป → ระบบจะโชว์ลำดับภาพที่เรียงแล้วให้ตรวจ
2. ตั้งค่าการต่อภาพ (ทิศทาง / การแบ่งไฟล์ / ชื่อไฟล์ / ชนิดไฟล์)
3. เลือกโฟลเดอร์ปลายทาง (ค่าเริ่มต้นคือ `<ต้นทาง>/_stitched`)
4. กด **▶ เริ่มต่อภาพ** → ระบบตรวจสอบให้ก่อน ถ้ามีจุดเสี่ยงจะถามยืนยัน

### แท็บ 2 — ต่อภาพหลายโฟลเดอร์

1. กด **+ เพิ่มโฟลเดอร์** ทีละอัน หรือ **+ เพิ่มโฟลเดอร์ย่อยทั้งหมด** เพื่อดึงทุกตอนในโฟลเดอร์แม่
2. ตั้งค่าครั้งเดียว ใช้กับทุกโฟลเดอร์
3. เลือกปลายทาง — ติ๊ก "แยกผลลัพธ์เป็นโฟลเดอร์ย่อยตามชื่อต้นทาง" เพื่อแยกแต่ละตอน
4. กด **▶ เริ่มต่อภาพทุกโฟลเดอร์** — โฟลเดอร์ไหนพัง ระบบข้ามแล้วสรุปให้ตอนจบ

## 🏷️ รูปแบบชื่อไฟล์ (name pattern)

| ตัวแปร     | ความหมาย                | ตัวอย่างผลลัพธ์ |
|-----------|------------------------|----------------|
| `{n}`     | เลขลำดับ                 | `1`, `2`, `3`   |
| `{n2}`    | เลขลำดับ 2 หลัก           | `01`, `02`      |
| `{n3}`    | เลขลำดับ 3 หลัก           | `001`, `002`    |
| `{folder}`| ชื่อโฟลเดอร์ต้นทาง         | `ตอนที่-12`     |
| `{total}` | จำนวนไฟล์ผลลัพธ์ทั้งหมด    | `5`            |

**ตัวอย่าง**

| Pattern              | ได้ไฟล์               |
|----------------------|----------------------|
| `{n3}`               | `001.jpg`            |
| `{folder}_{n2}`      | `ตอนที่-12_01.jpg`    |
| `page {n} of {total}`| `page 1 of 5.jpg`    |

> อักขระต้องห้ามของระบบไฟล์ (`< > : " / \ | ? *`) จะถูกแทนด้วย `_` ให้อัตโนมัติ

## 🛡️ ระบบกัน human error ตรวจอะไรบ้าง

ก่อนเริ่มต่อภาพจริง โปรแกรมจะสแกนแล้วเตือนเมื่อเจอ:

- **ไฟล์เสีย / เปิดไม่ได้** — บอกจำนวนและชื่อไฟล์ แล้วข้ามให้
- **ความกว้างต่างกันมาก** (แคบสุด < 50% ของกว้างสุด) — อาจเป็นภาพคนละชุด
- **ภาพที่ขนาดผิดปกติ** เทียบกับค่ามัธยฐาน — มักเป็นปก / โฆษณา / ภาพแทรก
- **ปลายทางอยู่ในต้นทาง** — จะทำให้รอบหน้าเอาไฟล์ที่ต่อแล้วมาต่อซ้ำ
- **ชื่อไฟล์ซ้ำในปลายทาง** — ถ้าไม่ได้ติ๊กเขียนทับ ระบบเติม `_1`, `_2` ให้

ทุกอย่างเป็นแค่ "คำเตือน" — คนตัดสินใจเองว่าจะไปต่อหรือยกเลิก

## 🗂️ โครงสร้างโค้ด

```
imbine/
├── config.py        StitchConfig — ค่าตั้งทั้งงานรวมไว้ที่เดียว
├── images.py        ค้นหา + เรียงไฟล์ภาพ (natural sort)
├── inspection.py    ระบบกัน human error (ตรวจก่อนทำงาน)
├── naming.py        แปลง pattern เป็นชื่อไฟล์
├── grouping.py      แบ่งภาพเป็นกลุ่ม (1 กลุ่ม = 1 ไฟล์ผลลัพธ์)
├── compose.py       งานพิกเซล: เปิดไฟล์ / ปรับขนาด / วางลงผืนผ้าใบ
├── output.py        บันทึกเป็น JPG / PNG / WebP
├── pipeline.py      กลไกท่อประมวลผล + ยกเลิกงาน + รายงานความคืบหน้า
├── steps/           ขั้นตอนมาตรฐาน (load, uniform, split, stitch, save)
├── api.py           run_stitch() — หน้าบ้านที่ UI เรียก
└── ui/               Qt frontend และ tk_app.py (legacy frontend)
```

**กติกาข้อเดียวที่สำคัญที่สุด:** ทุกอย่างนอก `ui/` ห้าม import Qt/Tkinter
`import imbine` จึงทำงานได้บนเครื่องที่ไม่มี UI binding หรือไม่มีจอ — มีเทสต์
บังคับข้อนี้ไว้ (`test_import_imbine_ไม่ลาก_tkinter_เข้ามา`)

## 🔧 ท่อประมวลผล (pipeline)

การต่อภาพถูกแยกเป็น "ขั้นตอน" ที่ต่อกันเป็นสาย:

```
load → uniform → split → stitch → save
```

แต่ละขั้นเปิด/ปิด/แทรก/สลับได้ทีละตัว ระบบที่จะเพิ่มทีหลัง (upscale,
denoise, watermark, auto-trim) เสียบเข้ามาโดยไม่ต้องแก้โค้ดเดิม:

```python
from imbine import Step, build_default_pipeline, run_stitch

class WatermarkStep(Step):
    name = "watermark"

    def run(self, ctx):
        for img in ctx.results:
            ...  # วาดลายน้ำลงบนภาพที่ต่อเสร็จแล้ว

pipe = build_default_pipeline()
pipe.insert_before("save", WatermarkStep())

run_stitch(paths, "output", pipeline=pipe)
```

ทุกขั้นต้องเคารพ 3 ข้อ: รายงานผ่าน `ctx.progress`, เช็ค `ctx.cancel`
ในลูปที่กินเวลา และห้ามแตะ UI

## 🧪 เรียกใช้เป็นไลบรารีก็ได้

ส่วนตรรกะไม่ผูกกับ Tkinter จึง import ไปใช้ในสคริปต์อื่นได้เลย

```python
from imbine import image_paths_in, run_stitch, StitchConfig

ctx = run_stitch(
    image_paths_in("chapter_01"),
    output_folder="output",
    config=StitchConfig(orientation="vertical", parts_count=3,
                        name_pattern="{folder}_{n2}", fmt="JPG"),
    folder_name="chapter_01",
    progress_cb=lambda e: print(f"[{e.step}] {e.done}/{e.total}"),
)
print(ctx.saved_paths)
```

**ยกเลิกกลางคัน** (สั่งจากอีกเธรดได้):

```python
from imbine import CancelToken, Cancelled

token = CancelToken()      # อีกเธรดเรียก token.cancel() เมื่อไหร่ก็ได้
try:
    run_stitch(paths, "output", cancel=token)
except Cancelled:
    print("ผู้ใช้ยกเลิก")
```

**ปล่อย `output_folder` ว่าง = ไม่เขียนไฟล์** ได้ภาพในหน่วยความจำอย่างเดียว
(ฐานของระบบ preview ที่จะทำต่อ)

ฟังก์ชันหน้าตาเดิม `stitch_images()` / `save_results()` ยังใช้ได้เหมือนเดิม

## 📄 ชนิดไฟล์ที่รองรับ

**ขาเข้า:** `.jpg` `.jpeg` `.png` `.webp` `.bmp` `.gif`
**ขาออก:** `JPG` `PNG` `WEBP`

> ภาพทั้งหมดถูกแปลงเป็น RGB ก่อนต่อ ดังนั้นความโปร่งใส (alpha) จะกลายเป็นพื้นหลังสีขาว

## ⚠️ ข้อจำกัดที่ควรรู้

- ภาพยาวมาก ๆ อาจชน limit ของฟอร์แมต — **JPEG กว้าง/สูงได้ไม่เกิน 65,535 px**
  ถ้าต่อยาวกว่านั้นให้ใช้ "จำกัดขนาดต่อไฟล์" หรือเปลี่ยนไปใช้ PNG
- ภาพถูกโหลดเข้าหน่วยความจำทั้งหมดก่อนต่อ — โฟลเดอร์ใหญ่มากอาจใช้ RAM เยอะ
- เรียงลำดับตาม "ชื่อไฟล์" เท่านั้น ถ้าชื่อไม่สื่อลำดับ ให้เปลี่ยนชื่อไฟล์ก่อน
